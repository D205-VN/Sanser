# Audio, drawable orientation and floating voice controls after 2.2.17

## Windows host sound missing on the legacy Mac client

The multiplexed audio listener consumes bytes from the main UDP demultiplexer.
It does not receive a second sender address from `recvfrom`. Its dedicated-socket
peer lock nevertheless accepted the first empty endpoint and rejected every
subsequent one because family zero is not a valid UDP peer. This could deliver
only one audio block while video continued normally.

The queued path now uses the main socket's existing peer validation. Dedicated
audio sockets still lock and reject unexpected senders. Packet authentication,
encryption and replay checks are unchanged. The regression checks 200 queued
blocks and dedicated-port rejection. With the old acceptance rule restored, the
test fails; with the fix it passes.

This fixes a confirmed missing-audio path. It does not establish hardware sound
quality for every Windows endpoint, or claim all crackling has been resolved.

## Upside-down Windows sharing on the SNV2 Mac viewer

An extra image flip combined with Core Image's convenience texture-rendering
defaults inverted the actual Metal drawable. The previous shared offscreen
texture fixture did not reproduce it.

Rendering now supplies an explicitly flipped `CIRenderDestination` instead of a
second canvas transform. Tests read back both an offscreen texture and a real
`CAMetalLayer.nextDrawable` texture using a GPU blit. Red top/blue bottom, colors
and letterboxing are checked for synthetic and VideoToolbox-decoded pixels.
The previous rendering implementation fails the new drawable test; the explicit
destination passes. The production renderer handles render-task failure without
throwing out of the Cocoa draw callback.

## Join state and on-screen voice controls

Sending a command to native stdin is not a native status acknowledgement. A
refresh immediately after Join could read the earlier idle record and reset the
UI to Join. The store now rejects stale reads and waits for matching state,
explicit failure or a bounded confirmation timeout. Mute/Leave retain the known
capture indicator until the engine confirms they have taken effect.

Both group hosts and viewers now create a native, nonactivating floating panel:

- Compact **Sanser · Voice**, with microphone state while participating.
- Expand to Join, Unmute/Mute, Deafen/Hear voice and Leave.
- Join listens only; Unmute is the explicit microphone consent action.
- Collapse and page navigation preserve an active call with visible controls.
- Disconnect, ending sharing and engine exit close the panel and capture.

Native status snapshots and panel commands use the existing voice worker and
bounded queues. The panel does not capture or encode audio on the GUI thread.
The floating capability is obtained from the probed engine, not a status string.
Older engines without `groupVoiceFloatingControls` still leave on navigation,
after any queued unmute, rather than keeping an invisible microphone active.

## Validation boundary

Local checks include frontend type/lint checks, 248 frontend tests, 89 desktop
Rust tests and the 28-test macOS native suite. Actual native panel buttons are
exercised using injected state and command callbacks on macOS; the Windows test
uses the same fake-state approach and runs in Windows CI. These tests never
open a microphone, play hardware audio, or capture another application.

Physical Windows/macOS calls still need verification for real microphone
permissions, audio devices, shared music, full-screen use, page navigation and
shutdown. This change does not claim to repair Internet route RTT or prove an
end-to-end latency target. No new installer is published by these source changes.

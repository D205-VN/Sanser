# Sanser review — 2026-09-21

The Mac Host error is still a deployment blocker: the running server rejects the
new role fields. Updating the desktop cannot correct an older API deployment.
Read-only checks of `https://sanser.onrender.com/api/v2/health` and `/readiness`
returned `ok` / `ready`, version `2.0.8`, protocol 2, without the new feature list.
No production deployment or database mutation was performed during this review.

## Corrections

- Host negotiation now cancels when sharing stops, the user stops a session, or
  polling observes that the remote client ended the accepted session. Cancelled
  direct attempts do not fall back to relay or launch a new native process.
- Shutdown waits for pending registration cleanup and native launches before
  allowing another host lifecycle. Old polling, heartbeat, credential and
  acceptance responses cannot restore the previous state. A late acceptance is
  disconnected.
- Native startup errors remain visible across successful request polling. If
  native shutdown fails, the app retains the sharing state and exposes another
  stop attempt instead of reporting a private/offline computer.
- The Mac Host page distinguishes an unsupported server from normal offline
  state and provides **Check again** after a server update. Stop session remains
  usable during connection preparation.
- Server health/readiness responses advertise `device-roles` and
  `cross-platform-native`, so deployment checks do not rely on a version string
  shared with older builds. See the [upgrade instructions](../apps/server/README.md#upgrading-for-mac-hosts-and-windows-clients).
- Database integration tests are explicitly marked ignored in default Cargo
  runs. Running them with `--ignored` requires `TEST_DATABASE_URL` and fails if it
  is absent; missing database configuration no longer looks like five passed
  database tests.
- Updated devalue to 5.9.4 and Vitest to 4.1.11, plus patched versions of
  brace-expansion, js-yaml, nanoid and postcss. These address the audit findings;
  package installation reported zero remaining vulnerabilities. The upstream
  advisories for [devalue](https://github.com/sveltejs/devalue/security/advisories/GHSA-9rgm-9g3h-6x36)
  and [Vitest](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9)
  describe their scope. This is dependency remediation, not evidence that Sanser
  was exploited.

Native tests use synthetic frames and loopback sockets. They do not establish
real screen-capture permissions, Windows compilation/execution, or stable video
between two physical devices across different networks. `TEST_DATABASE_URL` was
not configured, so migration and database-backed API behavior were not exercised.
The database suite must run against a dedicated Neon test branch/database before
its results can be claimed. Windows/macOS device-pair checks and real WAN testing
remain outstanding. Do not interpret the passing local checks as “all bugs fixed”.

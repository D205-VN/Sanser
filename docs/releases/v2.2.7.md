# Sanser 2.2.7

Mac viewers no longer resolve the SNV2 presenter to the legacy client's
`SanserMetalView`. That class-name collision caused an unrecognized `presentPixels:`
selector and an abort when the first decoded picture arrived. The SNV2 presenter
has a distinct name. A regression test links both real engines, checks the
required selectors and submits a decoded pixel buffer; it failed before this fix.

Windows now performs NV12-to-BGRA conversion on a separate worker with one
pending decoded picture. Slow conversion discards old independent pictures
without blocking H.264 reference decoding or triggering encoded-queue resets.
Input/control reception stays on its existing independent socket reader. Cold
decoder startup preserves up to 30 encoded frames within the existing 8 MiB cap
until the reference decoder catches up, then returns to the three-frame limit.
This avoids repeatedly resetting a cold decoder before its first output. The
Media Foundation decoder requests its documented low-latency mode. A fixture
containing 45 changing VideoToolbox H.264 frames at 1846×1200 exercises the real
Windows decoder and conversion path. The renderer respects the decoder's display
aperture instead of stretching H.264 macroblock padding into the desktop image.
The reported physical sharing freeze must
still be retested on the affected computers; successful unit tests alone do not
prove that every network/capture failure is fixed.

The first click after resuming Windows control now forwards both mouse-down and
mouse-up and restores focus. Keyboard messages with a missing scan code use a
virtual-key fallback, and keypad mappings are expanded. Mac host input uses a
private event source, explicit click counts and matching button event numbers,
modifier events and complete button/key release on reset. Hosting with input
also checks permission to post events instead of silently accepting unusable
input. Tests construct events without injecting them into the user's desktop.

Restoring the Windows app from a second launch applies show, unminimize and focus
in one UI turn, so a delayed restore cannot undo the next minimize action.

Install this version on **both computers**. For ordinary Windows → Mac control,
enable **Host → Remote input** and allow **Accessibility** for Sanser on the Mac.
Raw modifiers use the host Mac's conventions: Control remains Control and the
Windows key corresponds to Command. Windows may reserve some system shortcuts
before the viewer receives them. This release does not add full Windows IME text
composition forwarding. Group sharing remains **view-only**, with up to three
viewers; clicking/typing in a group viewer does not control the host.

The Mac → Windows system audio path from 2.2.6 remains included. Existing WAN
route latency, public UDP relay deployment, route migration and privileged
Windows Secure Desktop support remain separate work. Mac packages remain ad-hoc
signed; a changed signature may require granting permissions again.

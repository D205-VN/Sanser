# Sanser 2.2.13

Desktop latency diagnostics, bounded connection recovery and safer input/video
queues on the existing native Windows/macOS backends. Install this version on
both computers. There is no new database migration for this release.

## Included development milestones

- Shared network/session foundations remain in use. Ordinary Mac controlling
  Windows retains Legacy H.264/HEVC; Windows→Mac, Mac→Mac, Windows→Windows and
  group sharing use SNV2. This release does not force a protocol migration.
- Settings → Diagnostics shows common Legacy/SNV2 timing stages, bounded
  observation P50/P95 and queue/processing findings. Control application RTT,
  wire estimates and input ACK are distinct. Missing/stale stages stay unknown.
- A lost accepted native session can reconnect with fresh credentials/candidates,
  at most twice automatically. Direct/Relay choices and view-only permissions
  are retained. Disconnect cancels recovery; session-scoped cleanup cannot stop
  another session. Reconnect visibly reopens the remote window, not seamlessly
  migrates a live socket. High application RTT alone does not trigger reconnect.
- SNV2 host input executes on a separate bounded worker, preserving ordered
  actions and coalescing adjacent mouse moves. Slow OS input cannot hold UDP
  pong/receipt ACK handling. ACK/SACK removes obsolete queued sends; retries
  start when selected for the socket, back off and remain bounded. Legacy/SNV2
  share the retry formula. Reset/Disconnect releases held input on its worker.
- **SNV2 input ACK confirms ordered queue acceptance, not OS execution.** Numeric
  host input queue/work timings are sent back to the viewer to expose execution
  lag separately. No keystrokes, coordinates or credentials are added to reports.
- The shared decoder expires stale waiting chains, lets fresh IDRs replace older
  queued work, limits recovery requests and contains cleanup/recovery callback
  exceptions. Windows and Mac keep their existing optimized OS codecs/renderers.
- A read-only four-direction performance-matrix tool keeps per-run stage
  measurements separate and labels missing cases explicitly. See
  [input details](../input-engine.md), [route recovery](../route-recovery.md),
  [measurement contract](../native-performance.md) and
  [final video/validation work](../media-pipeline-validation.md).

## Validation and practical limits

Automated coverage includes authenticated UDP loopback under slow input,
ACK/SACK loss/reordering, input/reset capacity, decode backpressure/expiry/fresh
IDR, codec ownership/cleanup failures, real synthetic VideoToolbox/MF fixtures,
session cancellation/recovery races, diagnostics privacy and matrix semantics.
The release workflow produces Windows x64 setup/portable executables, macOS
Apple Silicon DMG/ZIP, signed updater bundles/manifest and SHA-256 checksums.

One eight-second **synthetic** run per network model delivered about 60 FPS on
emulated LAN and 58.75 FPS on the lighter WAN. The congested model (15 Mbps,
2% loss, 60±20 ms one-way) received its first picture only after 3.53 seconds and
**failed** the two-second video-gap gate, despite retaining all reliable input
in order. This is an unresolved stress-case limitation, not a passing latency
claim or a controlled regression comparison. See the
[unmodified numeric results](../benchmarks/native-network-2.2.13.json).

These tests do not certify physical capture permissions, GPU/driver stability,
all NAT/VPN routes or screen-to-screen latency on two real computers. A roughly
200 ms Internet route is not proven to become 10–15 ms. Public UDP relay needs
an actually reachable UDP server; WSS fallback still has TCP limitations.
Group sharing remains view-only/video-only, limited to three viewers. Mobile
clients, group audio and seamless route migration remain future work.
Ad-hoc Mac signing may require regranting screen-recording permission after an
update when Developer ID credentials are not configured in the release workflow.

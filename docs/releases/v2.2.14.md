# Sanser 2.2.14

Session stability fixes for native Windows/macOS control and group viewing.
Update **both desktops** for the new SNV2 input recovery extension. Update the
server as well to enable graceful Relay shutdown; there is no database migration.

- **Relay reset recovery:** retain the owning session and Relay failure even if
  the native engine has already stopped before status polling. An abrupt
  `Connection reset without closing handshake` can now reach bounded route
  recovery instead of being hidden behind a later input timeout. Recovery waits
  through a brief API outage, for at most 30 seconds, and always obtains fresh
  authorization/credentials before relaunch. Revoked consent is not retried as
  an outage. The native window reopens; this is not seamless migration.
- **Server shutdown:** send WebSocket Close 1012 (`server-restart`) during a
  controlled restart, with a bounded close-write deadline. Relay stop logs
  distinguish restart, policy/rate limit, replacement, read/write and control
  congestion. UDP Relay's WebSocket control also receives restart notification.
  Forced process kills, proxy resets and Internet failures can still interrupt
  WebSockets without a closing handshake.
- **Input ACK safety:** validate events before reserving reliable sequences;
  a view-only Windows viewer no longer emits focus-loss Reset. Supporting SNV2
  peers suspend input on ACK expiry, discard obsolete queued retries and perform
  an authenticated reset with a sequence fence. Only its matching confirmation
  can resume input. If reset confirmation fails within five seconds, video can
  continue but input stays disabled until reconnect. A separate host lease
  releases held input when the suspended viewer stops renewing it. Older peers
  retain the previous fail-closed stop rather than an unsafe unconfirmed resume.
- **One immediate cursor for control:** Mac host captures omit the streamed
  cursor during remote control; view-only/sharing captures retain the host
  cursor. The viewer keeps its local cursor.
- **Viewer X disconnects:** explicit Legacy/SNV2 viewer-close markers propagate
  through Rust/Tauri to server Disconnect and session-scoped Relay cleanup.
  A group viewer closes only its own session. Closing the Windows main shell
  to the tray remains separate. Delayed old cleanup cannot clear a new session.
- **Group video references:** replace the per-viewer single encoded-frame slot
  with a bounded reference-chain queue (eight pictures / 8 MiB). A brief dispatch
  delay no longer necessarily discards an IDR/P reference; overload still sheds
  the dependent chain and requests a fresh IDR with existing backoff/isolation.
- **Windows capture pause:** report authenticated capture-unavailable state,
  suspend viewer input, retain transport heartbeats, clear cached GPU frames and
  request a fresh keyframe when DXGI recovers. This does not grant access to
  UAC Secure Desktop or install a privileged Windows service.

Validation includes authenticated input ACK loss/reordering, reset mismatch and
duplicates, obsolete actions before the reset fence, expired confirmations,
held-input lease release, shared encoded-frame bursts, independent viewer
disconnect, 25-second video/capture pauses with native and WSS control alive,
abrupt WebSocket reset, server Close 1012 and UI authorization/cleanup races.
Fixtures use synthetic bytes; they do not capture a physical desktop or inject
real keyboard/mouse input.

**Limits:** group audio remains unimplemented (sharing is still view-only and
video-only, up to three viewers). No claim is made that every physical Share
freeze, UAC/driver failure or roughly 200 ms route is fixed. Retest Direct/Relay
and both control directions on real machines; a ten-minute multi-viewer capture
test remains necessary. See [detailed validation](../session-stability-2.2.14.md).

# Sanser 2.2.21

Update **both computers**. This release repairs Windows capture recovery and
input handling around application, desktop and display-mode transitions. App,
native engines, installers and signed updater artifacts use 2.2.21.

## Application and desktop transitions

- Recover transient desktop/GPU failures from capture acquisition, texture and
  mapping operations through the existing recreate path. Distinct DXGI access
  denial and abandoned synchronization no longer escape as fatal errors.
  Acquired resources are released before recovery; idle desktops do not trigger
  recreation. This shared capture backend serves Legacy and SNV2 Windows hosts
  and the already-authorized administrator helper.
- The SNV2 Windows injector updates its held-key/button state only when Windows
  accepts the operation. A rejected release remains available for a later Reset
  after recovery; rejected presses are never replayed.
- SNV2 pointer bounds now follow capture-generation changes after resolution or
  full-screen transitions. Input takes a synchronized rectangle snapshot instead
  of retaining the initial display size. Legacy already refreshed these bounds.
- Connection reports retain bounded capture error codes and input-rejection
  counts separately from network timing. App names, paths and input contents
  are excluded.

## Validation

Device-free tests cover transient/fatal capture errors, cleanup before recreate,
successful subsequent capture, rejected input transitions and pointer mapping
after a mode change. Native codec tests retain continuous-output/final-picture
checks and strict low-delay checks; the finite prerecorded source starts its
frame clock after first input consumption rather than overflowing during cold
Media Foundation initialization.

The sharing isolation fixture now offers independent pictures continuously
above the slow viewer's budget. Its former dependent chain could enter IDR
backoff, create clean recovery windows and legitimately reset pressure. Separate
tests still check IDR storm limits, reference recovery and verified viewer rejoin.
Production sharing thresholds and queue limits are unchanged.

The tagged build publishes Windows x64 setup/portable, Apple Silicon Mac DMG/ZIP,
signed updater bundles, updater-latest.json and SHA256SUMS.txt after source CI.

## Remaining real-device checks

Retry the affected app, its administrator window and full-screen/display-mode
changes separately. Check that capture resumes, pointer clicks stay aligned and
modifiers/buttons release correctly. Windows UAC support still requires the
installed, authorized helper; this release does not bypass Windows permissions.

These fixes do **not** prove every seconds-long freeze or WAN RTT spike is
resolved. Retained reports include both control delays and raw UDP echo spikes;
the exact launched-app reproduction has not yet been matched to those samples.
Existing audio, voice and group-sharing behavior remains subject to real-device
validation. Ad-hoc Mac updates may require recording/microphone permission again.

# Sanser 2.1.13

This release fixes stale host senders after a client retries an accepted session,
and bounds the Mac UDP client's wait for its first decoded frame. Update both
computers to receive the host and client changes.

- A client retry rotates its credentials and UDP endpoints even when the session
  ID stays the same. The host now cancels an outdated negotiation or stops its
  previous sender and relay before joining the new generation. Polling the same
  generation does not repeatedly restart the host.
- A negotiated Mac UDP viewer stops waiting after 20 seconds without a decoded
  frame and returns an error to Active session, where the connection can be
  retried. Errors distinguish receive silence, unexpected peers, missing video,
  video authentication rejection, incomplete packets and decoding failure.
  Standalone listeners and established streams are not subject to this startup
  deadline. Auto and Ultra both service receive timers during network silence.
- Bounded local connection reports record numeric startup counters and the
  `awaiting-video` / `startup-timeout` states. Control packets and overlay draws
  alone do not mark video startup complete. No peer addresses, credentials or
  screen/input contents are added to these reports.

Regression tests cover replacing running and in-flight host generations, failed
sender shutdown, the first-frame deadline, idle desktops and report persistence.
The reported black-screen sessions had no video reaching the Mac reassembler;
their exact Windows-side cause still requires device logs. This release does
not claim that all black-screen causes or physical network latency are resolved.

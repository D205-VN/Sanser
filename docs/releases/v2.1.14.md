# Sanser 2.1.14

This release adds one automatic recovery attempt for a Mac UDP viewer that
times out before its first decoded frame, and keeps connection errors visible.
Update both computers for the current host/client fixes.

- Explicit startup failures for missing UDP/video, unexpected peers or incomplete
  video packets trigger one fresh negotiation with new credentials and endpoints.
  The selected Direct, Auto or Relay mode is preserved. This does not force a
  Direct connection through relay.
- Recovery stops after one attempt, including when authorization or negotiation
  fails. The limit survives navigation between pages. Manual Retry or a new
  session resets it. Disconnect and a session closed by the host cancel recovery.
- Closing the viewer, an unclassified process failure, authentication rejection
  or a decoder failure does not automatically reopen the viewer.
- Session polling no longer erases native errors or overwrites freshly issued
  credentials with an older response. Transient polling errors still clear when
  polling recovers. Delayed cleanup cannot update a different session's state or
  stop its relay.
- Navigating away during negotiation releases the busy state after cancellation
  finishes, allowing the connection controls to be used again on return.
- Native startup failures have explicit internal categories; the UI shows their
  readable explanations without the internal marker.

Regression checks cover retry limits, navigation, manual retry, cancellation,
closed sessions, delayed cleanup, stale polling responses and error retention.
This improves recovery and diagnosis; it does not establish the cause of every
black screen or guarantee a particular latency on physical Windows/Mac devices.

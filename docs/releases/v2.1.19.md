# Sanser 2.1.19

Direct P2P now measures candidate paths before nomination instead of immediately
choosing the first bidirectional success. The controlling peer collects for up to
500 ms, takes up to five unique RTT samples per successful pair, and chooses by
median RTT, jitter and measured loss. Candidate/interface priority breaks ties.
A short remaining timeout can use fewer samples, explicitly marked in Diagnostics.

- Preserve authenticated endpoint discovery and the shared nomination handshake.
- Show advertised local/remote candidate types and endpoints, authenticated peer
  endpoint, probe sample count and median/min/max RTT in Connection details.
- Compare locally measured probe RTT with live Wire RTT after video warm-up.
  Three consecutive large increases create a warning and are retained in the
  local connection report. Stale attempt events cannot overwrite the current route.
- Keep Ctrl + Option + 8 for the Mac overlay. No automatic route migration is added.

Update **both computers**: an older controlling peer can still choose the first
success. Connect again, open Settings → Diagnostics → Connection details, and
compare probe median with Live Wire RTT while moving windows for 10–20 seconds.

Local validation: 62 P2P tests, 47 desktop tests, 145 frontend tests; Clippy, frontend
lint/type checking and production frontend build passed. The UDP test includes a
~200 ms route that succeeds first and a faster ~14 ms route that appears later.
Internet latency on the user's actual two networks is not yet verified; this
release does not promise a 5–15 ms end-to-end result.

See the [selection and measurement guide](https://github.com/D205-VN/Sanser/blob/v2.1.19/docs/direct-route-selection.md).

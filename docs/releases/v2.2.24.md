# Sanser 2.2.24

Update **both Windows and Mac**. This release improves audio recovery after
headphone/speaker changes, preserves fresh audio after a scheduling stall,
starts video repair earlier and fixes two sources of group voice distortion.
App/native versions and signed updater bundles are all 2.2.24.

## System audio and headphone changes

- After dropping expired Opus packets, resume from the fresh head rather than
  synthesizing PLC for intentionally retired audio. The previous timing could
  age additional fresh packets into the discard deadline.
- Windows loopback capture follows default output changes even when the old
  endpoint remains valid. A temporarily missing endpoint retries capture.
  Partial PCM/codec history resets without reusing authenticated packet numbers.
- Mac playback tracks device, same-device jack/source and sample-rate changes.
  It recreates the output queue and ramps in the first millisecond, including
  when the old output still reports running. Allocation/start errors retain a
  bounded retry path.
- A transient UDP audio send failure drops that packet and allows fresh audio
  to continue instead of permanently ending the audio capture worker.
- Sanitized reports add numeric freshness-reset, output-route-change and
  audio-send-drop counters. They do not retain device names or audio content.

## Video fragment repair

- An interior fragment gap can request repair after a 3 ms reorder grace before
  the frame tail or another frame arrives. Missing tails use a short stalled
  send grace. Reordered arrivals cancel unnecessary interior-gap requests.
- Keep the partial frame for recovery. Existing retransmit limits, dependency
  handling and newest-frame presentation remain bounded.

This reduces repair detection delay; it does not promise zero dropped frames
or 10 ms RTT during 200–400 ms Internet/Wi-Fi latency spikes.

## Group voice and microphone speech

- Keep AEC-processed and dry microphone speech on the same 5 ms timeline.
  Missing render reference no longer repeatedly resets the preprocessor or
  switches speech between different delays. Blend changes between the paths.
- Preserve in-range mixed PCM instead of applying `tanh` to every sample. Use
  stateful Opus soft clipping only where the mixed signal needs limiting.
- Numeric voice diagnostics distinguish concealment, FEC attempts, microphone
  clipping, playback underflow and AEC/reference gaps without recording speech.

## Validation and remaining checks

The [source baseline passed all nine CI jobs](https://github.com/D205-VN/Sanser/actions/runs/40304451213),
including **38 Windows native tests**, **32 Mac native tests**, authenticated
audio packet/epoch/reset tests and simulated transient UDP failures. A virtual
40-second output test covers headphone/source/device/rate changes without
opening a speaker. The new freshness regression fails against the 2.2.23 audio
implementation and passes with this repair. Source policy and installer builds
run again on the versioned release commit.

Physical Mac/Windows headphone hot-plug, long listening, three-person voice
with loudspeakers and real-network frame-drop P50/P95 still require testing.
The synthetic tests establish specific recovery behavior, not a guarantee
that every crackle, freeze, game input limitation or UAC transition is fixed.
Mac recording/microphone permission may need to be granted again after an
ad-hoc-signed update.

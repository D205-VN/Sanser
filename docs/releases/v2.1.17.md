# Sanser 2.1.17

Install this version on **both Windows and Mac** to enable the new Direct UDP
control/input timing measurements. Updating only the Mac displays the new rows,
but an older Windows native host cannot return the required timestamps.

- Measure enqueue, socket send, host receive/dequeue, pong/ACK send, client
  receive and reply processing (T0–T6) using each machine's monotonic clock.
- Show application RTT, socket RTT, estimated wire RTT, local queue times, host
  processing, shared UDP send-lock wait and send-call duration separately.
  The wire estimate still includes OS queues and scheduling before socket receive;
  no unsynchronized one-way network delay is claimed.
- Stop mixing input ACK/retry RTT into the control-ping RTT accumulator.
- Save allowlisted numeric timing metrics in local connection reports. Per-attempt
  probe IDs prevent matching a late ACK to a newer retry. Timing receipts use the
  existing control authentication; missing measurements display a dash.
- Change the Mac overlay shortcut to **Ctrl + Option + 8** (top number row).

This is a measurement/correctness release, not a claim that the reported
180–200 ms delay has already been resolved. Keep the Direct session settings
unchanged and compare the new rows before changing scheduling or splitting
sockets. Auto/Ultra buffering and relay transport are unchanged.

Automated checks cover authenticated UDP ping/input transmission, timing receipt
validation, queue decomposition across unrelated host/client clock epochs,
per-attempt matching, missing receipts and bounded report storage.

See [Direct timing guide](https://github.com/D205-VN/Sanser/blob/v2.1.17/docs/direct-control-timing.md).

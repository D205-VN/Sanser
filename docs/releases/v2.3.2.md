# Sanser 2.3.2 — Mobile Direct and bounded media latency

Android and iPhone now try authenticated Direct UDP before WSS Relay. Direct uses
the desktop Rust P2P core, STUN, measured candidate nomination and the same UDP
socket from gathering through media. Failed/cancelled attempts release their
reserved sockets. Forced Direct reports an error instead of silently relaying.
Duplicate mobile interface addresses no longer collide in candidate IDs.

iPhone H.264 decoding moves off the UI thread into a dedicated VideoToolbox
worker. Compressed reference frames stay ordered; only decoded images are
replaced in a one-image presentation slot. This avoids requesting a keyframe
merely because Flutter/UI work temporarily delays presentation. Android drains
to the newest decoded image and polls delayed output without waiting for the
next incoming frame. Recovery requests are bounded. These changes aim to reduce
backlog and stutter; measured WAN/device improvements still require testing.

Mobile defaults to a 6 Mbps video ceiling, configurable at 2/4/6/8/12 Mbps.
Updated SNV2 hosts honor this authenticated limit, start conservatively and
reduce bitrate when sustained RTT inflation indicates queue buildup. Pacing
uses the live bitrate budget. FPS is preserved during network adaptation.
Both desktop hosts should be updated to apply this receiver policy.
The mobile pacing/quality policy requires explicit receiver negotiation;
desktop peers retain their existing burst, serialization and quality bounds.

iPhone system audio uses a continuous, bounded PCM source with short crossfades
at underrun/overflow and rebuilds the audio graph after route changes. Mobile
settings, draggable/collapsible/hideable controls, automatic landscape, visible
transport status and cancellation/disconnect handling are included.

Validation includes Dart analysis and 27 Flutter tests, 97 Rust P2P/mobile tests,
native UDP interoperability/PCM/rate-control tests, and real H.264 VideoToolbox
tests with a blocked UI loop, stale-session rejection and decoder restart.
Builds do not establish Internet RTT or speaker/headphone quality on every phone.

Android APKs are signed locally with the existing Sanser keystore; no Android
signing key is uploaded to CI. The iPhone IPA is Release/AOT ARM64 and unsigned:
each recipient must sign it before installation. It is not a universal
tap-to-install or TestFlight build. See `README-iPhone-install.md`.

Mobile remains a preview: no microphone/group voice, mobile hosting, UDP Relay,
native IPv6 media or full Unicode/IME input. School/guest network isolation and
some NATs can still require Relay. No fixed 5–15 ms Internet latency is promised.

# Sanser 2.1.12

This release targets Windows send/pacing stalls and corrects the Mac arrival
jitter measurement. Update both computers to use all changes.

- Windows UDP pacing now uses a high-resolution waitable timer, avoiding coarse
  sleeps between small datagrams. The existing Ultra pacing budget remains 3–5 ms;
  actual send time can still exceed it because of socket, crypto or OS delays.
- Video/audio/control no longer share one HMAC lock. Fragment buffers are reused
  within each video packet without changing encryption or the wire protocol.
- The overlay separates **Send total**, **Pacing wait** and **Timer overshoot**.
  Authenticated host timing, including socket submission time, is saved in the
  Mac's bounded connection report so a slow Windows sender can be investigated.
- Arrival jitter uses sender timestamp differences and is sampled before the
  reorder buffer. Source cadence changes and local reorder waits no longer
  inflate this value by themselves. This is a measurement correction, not proof
  that network latency decreased.

Bitrate, resolution, reference-frame recovery and the newest-frame renderer are
preserved. Windows close-to-tray hosting from 2.1.11 remains available. This does
not change Direct/Relay negotiation or move the server from Render to a Mac.

Regression checks cover source idle/cadence changes, real arrival variation,
single sampling before reordering, generation reset, report persistence and
Windows timer re-arming. Actual latency on the user's Windows/Mac pair must be
measured after installing; no 5–15 ms guarantee is made.

# Sanser v2.1.8

This release targets unnecessary Relay fallback and Windows-host video latency when controlling Windows from a Mac. Update both computers.

- Direct UDP checks now continue at a bounded rate throughout the negotiation budget, rather than abandoning peers that miss the first 1.8-second probe burst. A regression test reproduces a peer joining 2.2 seconds late.
- The Windows-to-Mac native path can keep capture, cursor composition, scaling, NV12 conversion and hardware encoder input on the capture GPU. Auto selection prefers an encoder from the capture GPU vendor. Capture textures and encoder input surfaces use bounded pools. Unsupported GPU/driver paths fall back to CPU input, then software encoding if needed; rotated displays retain the compatible CPU path.
- Live asynchronous encoding drains available output and skips unencoded captures when the encoder is busy instead of blocking the stream for seconds. A watchdog detects a stalled encoder. Idle desktops poll encoder output without resubmitting duplicate frames, so the final output is not left waiting for another screen change.
- Capture timestamps now preserve elapsed time through slower capture, idle periods and encoder restarts. The stream no longer fabricates one nominal frame interval for every packet, which could make the Mac discard valid images as late.
- Video retransmission now has a short repair deadline measured on the host, a smaller request queue and a byte-bounded cache. Expired repair work yields to fresh video; authenticated input/control remains separate.
- Server settings are available in the sign-in screen and Settings → Network. An explicit custom HTTPS endpoint survives app upgrades; changing servers signs out and saved credentials remain bound to their original server. Existing users retain the packaged default endpoint.
- Added a macOS self-host setup command and documentation. It is opt-in: installing/updating Sanser does not start a server, open a tunnel or install a LaunchAgent. A temporary Quick Tunnel can expose a server behind NAT, but does not guarantee a local relay route or 5–15 ms latency. Account storage remains the configured Neon database.

## Validation and measurement

Windows CI compiles both native engines and exercises software H.264 encoding with irregular capture timestamps, WARP texture readback/cursor fallback, authenticated transport and loopback. macOS native tests and Rust/frontend checks also run. CI does not establish NVIDIA/Intel/AMD hardware performance or physical Mac-to-Windows latency.

After updating, use Auto, confirm Direct/Relay in Diagnostics, reproduce movement for around 30 seconds and export reports on both machines. Compare network RTT, host work, encode/decode and render queue measurements. Reports include GPU input activation and captures skipped under encoder backpressure. Capture/encode CPU timings are not a GPU completion measurement or synchronized input-to-display latency. No 5–15 ms result is claimed by this release.

Self-host setup: `docs/self-host-mac.md`. Both computers must use the same endpoint. A Quick Tunnel address changes when restarted and is intended for testing; use a stable named tunnel or appropriately configured network for lasting deployment.

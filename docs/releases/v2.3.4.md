# Sanser 2.3.4 — Workspace controls and experimental voice

Desktop and mobile product/build metadata use 2.3.4; the GitHub release tag is
`v2.3.4`. Update both desktop peers when testing. Enhanced voice remains a
separately configured, off-by-default experiment with the limitations below.

The workspace adds shared visual tokens and desktop/mobile session tools:
text/clipboard and file-transfer controls, keyboard/host shortcuts, mobile
tablet layouts and touch feedback, external-keyboard/controller handling and
network-recovery controls. Native platform backends still handle capture,
codecs, rendering and injection; a successful build does not certify every
device, game, elevated window or network path.

Voice Lab adds an experimental LiveKit/WebRTC voice path for desktop sharing.
It is **off by default** and requires a separately configured/deployed Sanser
admission gateway and private SFU signaling listener. Installing this release does
not provision a public voice server or enable enhanced voice on the existing
Render service. The native voice path remains available.

Windows native UDP now waits for readable data on a nonblocking socket rather
than repeatedly using very short blocking receive timeouts. This targets a
reproduced transport disconnect during a simulated long capture/UAC pause.
Opening the Windows host-shortcuts panel also leaves the remote OS unselected
until the user chooses it explicitly.

On a configured server, **Join enhanced voice** opens restricted floating
controls: host voice plus Stop sharing, viewer voice only. A scoped native
acknowledgement stops the previous mic/player before the new voice path starts.
Join is listen-only; microphone permission and Unmute are explicit. Capture or
publication that stalls fails after 15 seconds, with late results stopped and
unpublished. Old stopped-mic callbacks cannot mute a replacement. Output-device
changes retry playback without opening the microphone. A failed startup window
closes after approximately 25–27 seconds and restores shared sound.

Server admission validates current membership, login and device presence for
both cached and SFU-refreshed tokens. Room closure/retries survive restart;
closed rounds expire after 30 days in bounded batches, preserving active,
pending and leased work. See [deployment and acceptance](../livekit-voice-gateway.md).

## Known limitations

- Enhanced voice currently owns one desktop session at a time and pauses shared
  system music during the call to avoid loopback. Process-specific browser-audio
  exclusion and mobile enhanced voice are not implemented.
- Physical 2–3-person speech, echo/crackle, 3.5 mm jack changes, WebView permission/
  focus and long real-device sessions are not yet certified. Audible crackle,
  silence and latency are not declared resolved by synthetic tests.
- No public SFU/ICE/TURN deployment or WAN acceptance was completed. HTTPS alone
  does not provide the required media ingress. Direct may fall back to Relay
  on isolated Wi-Fi/NAT; no fixed Internet RTT is guaranteed.
- SFU/database outages may delay termination of an already connected peer.
- Mac builds without a Developer ID certificate remain ad-hoc signed; OS
  privacy permissions may need renewal. The iOS device IPA, if attached, is
  unsigned and requires recipient signing; it is not a universal installer.
  Android signing keys remain on the owner's Mac, never in GitHub secrets.

## Validation before packaging

- Desktop UI suite: 297 tests; subsequent voice-window consent/lifecycle checks
  pass. Voice Lab: 40 tests. Strict frontend typecheck/lint/build and Rust
  server/desktop Clippy pass.
- Isolated PostgreSQL: 13 API tests, including live authorization, closure retry,
  concurrent workers and bounded retention.
- Real local SFU: three synthetic Opus peers received two remote tracks each
  over 120,045 ms without a per-track three-second stall; all disconnected on
  group stop. The separate short trial denies cached and actual SFU-refreshed
  rejoin before the original token expires. No physical audio device was used.
- Native macOS synthetic audio/video gate and broadcast continuity tests pass.
  Platform CI/build outcomes and artifact signatures must be verified for this
  release commit before publishing installers.

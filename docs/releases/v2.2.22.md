# Sanser 2.2.22

Update **both Windows and Mac**. This release packages UAC helper readiness,
clearer capture-pause errors and Legacy Windows input acceptance fixes. The app,
native engines, installers and signed updater artifacts use 2.2.22.

## Windows UAC helper and capture

- A zero-input Probe → Ready handshake now establishes a new authorized worker
  before capture/input is submitted. Worker startup allowed three seconds while
  the caller previously waited only one second, so valid cold workers could be
  discarded before becoming ready. The handshake has a four-second ceiling;
  it returns as soon as the worker responds.
- First capture has a separate bounded cold-start deadline on both IPC sides.
  Steady response limits remain unchanged. This does not add a fixed frame or
  input buffer, and timed-out input is not replayed by the broker layer.
- Capture errors retain their HRESULT and desktop/session/input failures retain
  their status. Mac receives bounded numeric helper health over authenticated
  control; during capture pause its overlay shows the last helper failure/code
  instead of only a generic waiting message. Old hosts do not invent missing
  helper results. A historical failure is labelled as the last failure.
- Existing protected-path/account/session checks and desktop restrictions remain
  in force. UAC policy and desktop ACLs are unchanged; Windows sign-in/password
  desktop access is not added.

## Mac controlling Windows: input acceptance

- Legacy buttons, wheel, relative motion and keyboard paths no longer treat
  void compatibility APIs plus a stale GetLastError as successful input after
  normal/helper injection failed. Rejected scan-code keys are not replayed via
  another API. OS insertion still does not prove the target app acted on input.
- Rejected releases remain owned, including failed Reset, so a later Reset can
  release them after recovery. Reports distinguish OS direct/privileged input
  acceptance and rejection from receipt ACK timing, without retaining app names,
  typed content, paths or cursor positions in the new evidence.

## Validation and remaining physical checks

The source baseline passed [all nine CI jobs](https://github.com/D205-VN/Sanser/actions/runs/40186167992),
including 37 Windows and 30 Mac native tests. The isolated Windows service
fixture deliberately delays worker startup by 1500 ms and verifies actual
medium-integrity input on its elevated Cancel button, plus unauthorized Probe,
Capture and Input rejection. The delay is BUILD_TESTING-only; production builds
disable it. Mac tests cover authenticated helper-health parsing/status text;
Rust tests cover numeric filtering. Sharing fixtures now answer legitimate
keyframe requests while waiting, like the real encoder loop; runtime sharing
policy is unchanged. Versioned source checks and installer builds run again.

The Cancel fixture runs on Default, not an actual UAC consent screen. Retest the
affected Windows host: open the app, verify the UAC screen is visible and usable,
then check ordinary/elevated windows after consent closes. If it still fails,
the new helper stage/code should identify the next investigation step. This
release does not claim all FC Online restrictions, capture failures or WAN
latency spikes are resolved. Ad-hoc Mac updates may require recording/microphone
permissions to be granted again.

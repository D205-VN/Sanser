# Sanser 2.2.4

The desktop workspace has clearer computer cards, short computer identifiers,
online/offline status and a more prominent Connect/Share action. Card and list
views adapt to smaller windows. The sidebar shows this computer's sharing state;
the Host page separates remote input permissions from view-only group sharing.
Update remains visible only when a newer release is available. Diagnostics stays
inside Settings rather than adding another main navigation item.

Shared-keyframe recovery now coalesces requests per viewer. Repeated failures
retry after 500 ms, then 1 s, then at most once every 2 s. Three seconds without
a recovery signal restores fast recovery for a new incident, subject to the
group's existing request interval. Replacing a queued frame with a fresh IDR
does not request another IDR, and publishing one satisfies older pending demands
without treating it as proof that the viewer received it.

Native diagnostics emit per-viewer frame, queue-drop, keyframe-request, repair
and recommended-bitrate counters once per second. The shared encoder still
uses the lowest active viewer budget: this update does not provide independent
quality tiers, automatically remove slow viewers or increase the three-viewer
limit. All viewers still receive the same encoded stream.

Tauri JavaScript API and Rust runtime are aligned at 2.12.4; CLI is 2.12.3.
The protocol remains v2. The existing Windows single-instance/tray restoration
and buffered native viewer painting from 2.2.3 are included.

Local validation covered 164 frontend tests, type checking, lint, production
build and 13 native tests on Mac. A two-viewer authenticated UDP loopback test
with one viewer paced at 1 Mb/s produced 3 forced-keyframe requests over 240
published frames while the healthy viewer continued receiving. This synthetic
transport test does not prove real Windows/Mac capture or WAN performance.
GitHub CI also checks Windows native and desktop lifecycle behavior before the
release is tagged.

The previously observed 200–300 ms route RTT is not claimed fixed. PCP/NAT-PMP
integration, automatic path migration, public UDP relay deployment validation,
and privileged Windows Secure Desktop control remain separate work. Normal
capture recovery after a desktop interruption remains available.

Install on both machines to test the new sharing behavior, then test one-to-one
Direct separately from multi-viewer sharing. Keep the same quality settings when
comparing measurements. The Mac installer remains ad-hoc signed unless Developer
ID secrets are configured; after replacing a locally signed build, Screen
Recording permission may need to be granted again. See
[Mac permissions](../macos-permissions.md).

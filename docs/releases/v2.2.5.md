# Sanser 2.2.5

Slow screen-sharing viewers no longer remain in the shared bitrate minimum
indefinitely while repeatedly failing delivery. Sustained delivery pressure for
six seconds, or two-second keyframe backoff sustained for eight seconds, pauses
fresh video for that viewer. Control, keepalives and bounded repair remain alive;
other viewers continue. Recovery probes wait 5 seconds, then 10/20/30 seconds
after failures. A completed new frame and three clean feedback windows are
required before rejoining. The Host panel shows pause, probing and stopped
connections, and the watching count reflects these states. Sharing remains
view-only, limited to three viewers, with one common encoder and quality level.

Windows viewers decode and convert pixels on a dedicated worker rather than
blocking the UDP reader. Its encoded queue is bounded; overflow discards the
dependent chain, resets the decoder and requests an IDR. Decoder COM objects are
created and released on that worker. Input/control reception and window painting
continue independently of a slow decode. This addresses a concrete blocking path;
the reported physical-device freeze still needs a two-machine retest.

Reliable mouse/button/key delivery no longer disconnects Ultra sessions after a
fixed 120 ms without an ACK. A conservative initial delivery deadline and measured
ACK latency control bounded retry/backoff, allowing 200–350 ms WAN ACKs. Truly
unacknowledged input still fails closed within a finite 2–5 second bound to avoid
leaving keys/buttons held. This does not lower the underlying route RTT.

Sign-in sends the actual computer name, OS and a persistent non-secret
installation identifier. After password verification, the server atomically
replaces an older session from that same installation and account, without
merging different computers that share a name. Older anonymous sign-ins remain
available in a collapsed section for individual sign-out. The optional seven-day
remembered-sign-in policy is unchanged; passwords are not saved. Normal sign-in
uses the default server automatically, with an explicit option for custom servers.

Deploy the server from this release so migration `0008_login_installation.sql`
can enable session replacement. New apps can still sign in to older servers by
omitting only the unsupported installation-ID field on an explicit schema error;
replacement requires the server update. Install 2.2.5 on **both computers** for
completion-verified automatic viewer recovery. Older viewers without progress
feedback may remain paused until removed and invited again.

Validation includes frontend type/lint/build/tests, Rust desktop tests, native
policy and codec tests, a deliberately blocked decode-worker test, authenticated
UDP sharing with one constrained viewer, and a mouse-click regression with ACKs
delayed 350 ms. GitHub CI additionally checks the Windows build/native tests and
PostgreSQL integration, including concurrent sign-in replacement, account
isolation and rejection of superseded tokens, before publication.

The previously observed 200–300 ms WAN/overlay RTT is not claimed fixed. Real
Windows/Mac capture and Internet impairment tests remain necessary. Public UDP
relay validation, PCP/NAT-PMP integration, automatic route migration and privileged
Windows Secure Desktop control remain separate work. macOS installers remain
ad-hoc signed unless Developer ID secrets are configured; Screen Recording may
need to be granted again after replacing a differently signed build. See
[Mac permissions](../macos-permissions.md).

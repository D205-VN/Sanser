# Sanser 2.3.38

Exam supervision is much closer to live:

- **The grid refreshes every second:** each student computer takes a small
  picture (about 640 px, 20–30 KB) every second and sends it only when the
  screen changed, or every 10 s when nothing moved. Before, the grid
  refreshed every 10 seconds.
- **Live view of one student:** clicking a student opens a large view with
  about four sharp pictures a second (1280 px), enough to read code. It
  speeds up within a second of opening and goes back to the grid pace when
  closed. It is fast pictures, not video, so scrolling looks jerky.
- **Lighter on Windows:** screenshots come from one hidden PowerShell kept
  for the exam instead of a new one per picture. It ends with the exam or
  with Sanser.

Older student apps keep working with the new server: their picture still
rides in the heartbeat every 10 s (2 s while watched).

Server: new `POST /api/v2/exam-members/{member}/screen`, sequence numbers and
`?after=` on the screens list, `liveScreenSeconds`/`liveScreenMs` in the exam
policy. Memory only, no migration. Exam screen paths have their own limits
instead of the per-address one, since a class shares one school address.

Checks: server tests (79 + 20 with a database), desktop Rust tests, lint,
type check and unit tests (404) pass. The Windows screenshot process builds
in CI only and has not been tried by hand; on this Mac a 1280 px capture
takes about 0.2 s.

# Sanser 2.2.3

On Windows, launching the desktop shortcut while Sanser is hidden in the system
tray now restores and focuses the existing main window. The single-instance
plugin initializes before the webview and tray; a second launch exits without
starting another account, heartbeat, or host process. The same restore function
handles the shortcut and tray. Closing the main window still keeps hosting
alive; **Quit Sanser** in the tray exits the app.

The Windows native viewer paints each completed frame through a persistent
back buffer, eliminating the visible black clear before a software stretch.
During a move/resize, a temporary timer continues presenting the newest decoded
frame while Windows runs its modal window loop. The existing coalesced frame
notification and retained last frame remain in use. This fixes rendering paths;
it does not claim that every network/decoder source of stutter has been solved.

Windows CI exercises repeated close-to-tray/shortcut reopen cycles and restoring
a minimized window, checking that the original process and window survive and
secondary processes exit. Offscreen GDI tests cover image colors, orientation,
aspect ratio, resizing, minimized bounds, and graphics-resource cleanup.

The official single-instance plugin requires the desktop runtime to update to
Tauri 2.12 and Rust 1.90 or newer. The server and native protocol remain v2.
Mac and Windows desktops can use different patch versions within 2.2.x.

Before testing the new Windows build, quit any duplicate 2.2.2 instances already
running in the tray. Older processes did not register a single-instance guard.
Then install 2.2.3, close its main window, and launch the shortcut several times.
There should be one Sanser tray icon and the original window should reappear.
Also test a live remote stream while dragging/resizing the viewer window.

The macOS package still uses ad-hoc signing unless Apple Developer ID secrets
have been configured. A locally development-signed Mac installation is a
separate identity from that package; see [Mac permissions](../macos-permissions.md)
before replacing it. Real two-machine capture/network testing remains necessary.

# Sanser 2.2.20

Update **both the host and viewers**. This release packages group-voice timing
repairs, clearer floating controls, automatic viewer departure cleanup and host
connection alerts. App, native engines and signed updater bundles use 2.2.20.

## Group voice and floating controls

- Staggered talkers now share one playback clock. Independent speaker deadlines
  previously generated extra partial mixes, which could cause audio drops or
  queue growth when two or three people spoke. Each speaker retains independent
  Opus decoding, jitter buffering, FEC and PLC.
- A device-free comparison against 2.2.19 emitted 509/565 five-millisecond blocks
  for two/three talkers over the same interval. The repaired mixer emits 397,
  matching the single-talker playback schedule. This measures scheduling, not
  physical network or speaker latency.
- The compact host bar combines sharing and voice; viewers have voice controls
  only. Join and microphone state are clearer in the header; expanded controls
  have readable labels for mic, listening and Leave. Join listens only; Unmute
  explicitly enables microphone capture. Collapse does not leave the call.

## Viewer departure and host alerts

- Closing the remote viewer ends its session and sharing membership, frees the
  slot and updates the host's watching count. A sticky close marker is observed
  before native teardown completes, including startup. Failed server cleanup
  retries without reopening the closed viewer.
- The host can also clean up the one peer that explicitly disconnects. Native
  status distinguishes deliberate departure from recoverable transport errors
  and guards against an old path ending a replacement readiness generation.
  Other viewers and the sharing host remain active.
- Incoming access notices name the computer and show view-only or approved
  mouse/keyboard access, with Stop viewing/Stop access scoped to that session.
  Invitations alone do not announce a viewer as connected. Dismiss does not stop
  sharing, and polling does not repeat the same notification.
- **Host → Connection alerts → Enable notifications** enables desktop alerts
  while the shell is hidden. OS permission is requested only by this explicit
  action. In-app notices work without OS permission. Notification delivery
  rechecks session/account lifetime; no microphone/screen content is included.
- Closing the main Windows shell still hides it to tray. Leaving voice alone
  does not disconnect screen sharing.

## Validation and remaining physical checks

The source changes passed [all nine CI jobs](https://github.com/D205-VN/Sanser/actions/runs/39803486533),
including 269 frontend tests, 35 Windows native tests, 29 Mac native tests,
Rust checks and server integration. Release validation reruns checks at 2.2.20
and builds both installers plus signed updater artifacts.

Test two/three updated computers after installing: speak with staggered starts,
share system music, close one viewer while others remain, invite it again, and
verify the named host alert with the main shell hidden. Synthetic scheduling and
loopback tests do not prove every acoustic artifact, WAN delay or device-specific
problem is resolved. This release does not promise 5–15 ms Internet latency.

Downloads: Windows x64 setup/portable, Apple Silicon Mac DMG/ZIP, signed updater
bundles, updater-latest.json and SHA256SUMS.txt. Ad-hoc Mac builds may require
screen-recording/microphone permissions to be granted again after an update.

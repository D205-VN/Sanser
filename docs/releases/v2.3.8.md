# Sanser 2.3.8

This update targets video stutter and blur on jittery Wi-Fi paths. Update the
hosting computer for the bitrate changes, and the viewing device for the video
repair changes.

- Repair a picture that lost **every** fragment. It previously had nothing to
  request and its dependents waited about 390 ms for expiry and a new keyframe.
  The viewer now asks for its first fragment once a later picture arrives. The
  wire format is unchanged and existing hosts answer the request.
- Request a lost picture tail as soon as a later picture proves it left the
  sender's pacer, instead of waiting out the serialization estimate.
- Mac viewing Windows: a brief RTT rise or a stray repair on a mostly static
  desktop no longer lowers the target bitrate. Delay pressure needs the lowest
  of three consecutive samples to stay elevated. Loss while the stream is far
  below its target, or light fully delivered loss, does not reduce quality.
  Bitrate recovers after three clean seconds in 10–12% steps.
- Mobile viewers: moderate RTT rises must persist across three of four 250 ms
  probes before the video budget is cut or recovery is held; large spikes act
  as before. The budget recovers 10% after two healthy seconds, not 200 kbps
  per five.
- The Direct router forwards up to 16 datagrams per wake in each direction.
- Mac releases can be signed with a stable self-signed certificate (see
  `docs/macos-permissions.md`), so Screen Recording and Accessibility grants
  are meant to survive updates. This applies only once the repository secrets
  are configured; without them the build stays ad-hoc signed.

Trade-off: a genuinely congested path is recognised roughly half a second to
two seconds later than before.

The Mac/native transport suite passed 45 tests, the mobile native suite 6, and
`sanser-p2p` 95, including new regressions for whole-picture loss, tail loss,
jitter-only delay traces and app-limited loss. The Windows host changes were
not compiled or run locally; Windows CI is their first build. No physical
session has validated these changes yet. A measured Mac–Windows session before
them showed network RTT spikes (p95 about 89 ms on a 10 ms path) that this
release does not remove, adaptive FEC that sent no parity, and 10–15 ms of
Windows input-injection work; those remain open. This release does not claim
all stutter is eliminated.

Mobile version: 2.3.8, build 20316. Android is signed locally with the existing
owner-held key. The iPhone IPA is unsigned and requires recipient signing; it
is not an App Store/TestFlight installation. Existing Voice Lab deployment and
physical-device validation limitations remain unchanged.

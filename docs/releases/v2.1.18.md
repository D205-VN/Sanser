# Sanser 2.1.18

The Mac native client now receives and demultiplexes UDP on a dedicated thread.
Video reassembly/decode no longer occupies the socket receive loop, allowing
control replies, input ACKs and audio to be read while video processing is busy.

- Keep the existing UDP socket, negotiated endpoint and authenticated protocols.
- Bound the video receive queue to 1,024 datagrams and 50 ms maximum packet age.
  Video is processed immediately when available; 50 ms is a discard deadline,
  not an added playout delay. Overload uses existing sequence recovery and
  rate-limited keyframe requests, never decoding partial frames.
- Preserve the actual socket receive timestamp for T0–T6 control measurements.
- Add **UDP video queue** (per-window maximum residence time) to the Mac overlay
  and retain numeric queue/drop metrics in local connection reports.
- Join the receiver before closing its socket, including error/exception paths.

The overlay shortcut remains **Ctrl + Option + 8**. Update both computers to
2.1.18 for a consistent test setup. This change targets Mac receiving a native
UDP stream; Windows scheduling, Auto/Ultra repair policies and relay transport
are unchanged. A WSS relay can still contribute substantial latency.

Automated tests use real UDP sockets with video consumption deliberately stopped,
a full queue, expired packets and an unexpected peer. Control/audio bypass the
video backlog; dedicated video UDP and socket-error shutdown are also checked.
Real Windows→Mac latency and picture quality still need the two-device test.

For comparison, keep route and stream settings unchanged, record the negotiated
Direct/Relay route, and capture the overlay while idle and during movement.
See [timing guide](https://github.com/D205-VN/Sanser/blob/v2.1.18/docs/direct-control-timing.md).

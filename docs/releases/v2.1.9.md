# Sanser v2.1.9

Update both computers, choose **Settings → Stream → Ultra Low Latency**, then
reconnect. This opt-in preset targets client buffering and input responsiveness
on stable, low-latency networks. Other quality presets remain available.

- Mac controlling Windows: the render queue keeps the newest decoded frame,
  base pacing is zero, and Metal work is limited to one command buffer in flight.
  Frame arrival triggers a draw without waiting for the next periodic draw tick.
- The UDP reorder deadline is 12 ms in Ultra instead of 70 ms. Expired repairs
  are discarded; missing reference frames trigger keyframe recovery instead of
  feeding dependent frames into the decoder.
- Native SNV2 now has a dedicated paced sender with separate bounded priority
  lanes. Large video frames cannot occupy the input/control lane. Absolute mouse
  positions coalesce; reliable keys/buttons use negotiated selective ACKs and
  short retry intervals. An unrecoverable input gap terminates/reset the session
  instead of leaving an unbounded backlog.
- Existing Mac→Windows input already uses multiplexed UDP. Ultra shortens its
  retries and resets input when recovery expires. Connected gamepad snapshots
  replace old snapshots per controller; disconnect events remain acknowledged.
- The Mac→Windows native overlay shows measured capture, encode, send/pacing,
  network RTT, arrival jitter, decode, frame queue, GPU render and input ACK RTT.
  Toggle it with **Control+Option+F8**. Unavailable or stale samples show `—`.
  Windows CPU fallback produces a visible warning in Ultra.
- Local diagnostics retain the mode and queue/render measurements and flag
  delays against the tighter Ultra budgets.

The production Mac→Windows route retains its existing authenticated SNU2 wire
format and relative mouse/gamepad support. SNV2 platform sessions still do not
provide audio/gamepad; reserving an audio scheduling lane does not add that feature.
The detailed overlay currently applies to Mac controlling Windows.

Automated tests cover frame replacement, sender restarts, reordering/deadlines,
IDR recovery, input loss/duplicate suppression, selective retransmission,
priority scheduling, codec loopback and application integration. Physical
Mac–Windows latency and hardware-specific encoder performance require measurement
on the actual machines. A zero software pacing target is not zero display latency;
this release does not claim 5–15 ms end-to-end performance.

No server migration, tunnel or background service is enabled by this update.

Windows x64: `Sanser-Windows-2.1.9-x64-setup.exe` or portable EXE.
Apple silicon Mac: `Sanser-macOS-2.1.9-arm64.dmg`.
Signed updater bundles and SHA256SUMS.txt are included. The macOS app is ad-hoc
signed, not Apple-notarized; Windows has no Authenticode publisher certificate.

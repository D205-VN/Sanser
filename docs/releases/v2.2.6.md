# Sanser 2.2.6

Windows can now play system audio when controlling a Mac running macOS 13 or
later. Previously this cross-platform path had no Windows playback backend and
explicitly disabled SNV2 audio, regardless of speaker volume or preferences.

Install 2.2.6 on **both computers**. On the Mac enable **Host → System audio**;
on Windows enable **Settings → Audio → Session audio**, then reconnect. Allow
Sanser Screen & System Audio Recording on the Mac. Microphone capture is not
enabled. Group screen sharing remains video-only.

ScreenCaptureKit captures stereo system audio on a separate queue. Complete
5 ms PCM16 blocks travel as authenticated SNV2 UDP audio packets, without
fragmentation or retransmission. The viewer explicitly opts in; host or viewer
mute prevents delivery. Input/control retain priority over sound, and sound
precedes video. Queues drop old audio instead of accumulating delay.

The Windows WASAPI playback worker owns its audio devices independently of UDP
reception and video decoding. It retries missing/unplugged outputs and follows
default multimedia device changes without closing the remote desktop session.
Audio controls are shown only for engines advertising the new implementation;
legacy engine audio is not mistaken for cross-platform support.

Validation covers encrypted UDP delivery, both mute settings, older viewers,
bounded queues, input/control priority, PCM conversion and real CoreMedia planar
and interleaved sample buffers, plus frontend and Rust launch/capability tests.
Windows CI compiles the playback implementation. Physical speaker output,
Bluetooth behavior and end-to-end audio latency still need two-device testing.

This first path uses about 1.54 Mbps of PCM payload plus transport overhead.
Opus compression, adaptive audio clock/jitter control, group-sharing audio,
Windows-host SNV2 capture and Mac-client SNV2 playback are not part of this
release. Existing Windows → Mac legacy audio remains unchanged. The observed
200–300 ms WAN/overlay route RTT is not claimed fixed. See
[audio implementation and test notes](../windows-mac-system-audio.md).

All fixes from 2.2.5 remain included. Mac packages remain ad-hoc signed unless
Developer ID signing is configured; an updated build may require granting
Screen Recording again. See [Mac permissions](../macos-permissions.md).

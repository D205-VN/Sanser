# Sanser 2.3.14

This update targets sound on a Windows viewer, Windows-to-Mac copy/paste and
frozen viewers in multi-computer sharing. Update both computers.

- Windows viewer sound and group voice: audio threads now run at high
  priority, and playback and the microphone join Windows' "Pro Audio" (MMCSS)
  scheduling. Output keeps 30 ms in the device (was 20 ms) and the microphone
  buffer is 100 ms (was 20 ms). Before, a busy video decoder could delay the
  refill, heard as stutter in shared sound and crackle in voice.
- Shared sound on Windows viewers and phones: the receive jitter buffer
  adapts between 10 and 60 ms. A packet arriving after its slot grows it by
  10 ms without skipping audio; eight calm seconds give back 5 ms. A fixed
  10 ms reserve had concealed 8-27 of 200 blocks per second on Wi-Fi.
- Windows viewing a Mac with Text clipboard allowed: Ctrl+V first sends the
  Windows text to the Mac, then pastes (input waits at most 0.4 s for the
  write). After Ctrl+C or Ctrl+X the Mac text is copied back to Windows.
  Text only, up to 8 KB.
- Share with multiple computers: a viewer is no longer paused for frames the
  host skips while that viewer waits for a keyframe. A recovery probe fails
  only on two consecutive congested windows, and a pause lasts 3, 6 and then
  at most 10 s (was 5-30 s). A 2.3.10 log showed nine pauses in four minutes.

Trade-off: when Wi-Fi jitter grows the audio buffer, sound can lag video by
up to 50 ms more until the path is calm again.

Checks: new tests for the adaptive jitter buffer (periodic 25 ms jitter is
absorbed, calm playback shrinks the delay), the clipboard paste gate and the
sharing policy (frames skipped while waiting for a keyframe no longer pause a
viewer), plus the full Mac (47) and mobile native (6) suites. The Windows
audio and clipboard code was first compiled by release CI. No physical
Windows session has validated these changes yet.

Mobile version: 2.3.14, build 20322. Phones benefit from the adaptive audio
buffer after updating the app.

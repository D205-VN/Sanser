# Sanser 2.3.5

Update both computers to use the new selective video repair path.

- Mac audio output continuously feeds two fixed Core Audio buffers and binds
  the selected physical output. This addresses the reported Windows system
  audio becoming inaudible on the Mac viewer. In the local listening test,
  playback continued beyond the previous failure interval. Windows capture
  also retries temporary device failures without restarting transport keys.
- Legacy Mac-to-Windows video repair requests identify missing fragment
  ranges. The Windows host resends those fragments rather than replaying an
  entire encoded frame from its beginning. Completed-frame repairs are
  retired on the Mac to avoid phantom assemblies and redundant recovery.
  Request sizes, cache age and repair work remain bounded. Older peers keep
  whole-frame fallback.
- Direct socket setup retries supported receive-buffer sizes instead of
  silently retaining a small default on systems that reject large buffers.
  Candidate verification and mobile diagnostics distinguish exchanged
  endpoints from a verified UDP path; Wi-Fi 5 GHz is not cellular 5G.
- Mobile device registration retains the server's canonical device ID and
  repairs a conflicting restored ID once. Receive FPS uses the sampling
  interval rather than a fixed one-second assumption; view-only repair can
  use control RTT before a keyboard/button ACK exists.
- Numeric audio idle/output and video-repair counters improve diagnosis
  without exporting credentials or physical device names.

The receiver-only video trial did not eliminate the user's stutter or
periodic blur. Selective repair now changes both ends, and its real two-machine
effect still requires retesting. This release does not promise a fixed RTT,
zero dropped frames, or resolved voice/microphone crackle on every device.

Mac builds remain ad-hoc signed when no Developer ID certificate is configured;
macOS may ask for screen recording permissions again after updating. Existing
Voice Lab deployment requirements and mobile signing restrictions from
[2.3.4](v2.3.4.md) still apply. Android release keys remain on the owner's Mac.

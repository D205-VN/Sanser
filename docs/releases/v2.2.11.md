# Sanser 2.2.11

This release fixes two reproduced SNV2 video stalls affecting multi-computer
sharing in both directions and the transport used by Windows controlling Mac.
Update both computers. It does not establish that the user's separate slow WAN
route or every reported window exit has been resolved on real devices.

## Large desktop pictures must finish transmission

The old Ultra sender discarded video datagrams after 40 ms (Auto: 100 ms).
A 256 KiB keyframe needs about 100 ms just to pass through the configured
20 Mbps pacer. It was therefore cut off even on lossless localhost. The new
deadline accounts for serialization and video already queued, with a 500 ms
hard limit. Completed frames are delivered immediately; this is not an added
500 ms playout buffer. Priority control/input/audio lanes remain independent.

Fragment assembly uses a compatible, bounded recovery deadline. NACKs for
interior holes remain prompt, but the receiver no longer requests an entire
tail that is still waiting in the sender's pacer. The per-viewer retransmit
cache is retained for up to one second, 64 frames or 8 MiB, whichever limit is
reached first. Cache residency does not delay presentation.

## Do not request another IDR while the requested IDR is arriving

The receiver previously requested keyframes on fragments of an IDR it was
already assembling. A late request could put the sharing host back into its
"await keyframe" state after successful startup, suppressing subsequent
P-pictures. Requests are suppressed while an IDR is being assembled; failed
assembly still triggers bounded repair and keyframe recovery.

## Keep receive processing independent of the Mac decoder

The SNV2 Mac client now uses the bounded decode worker already used on Windows,
so VideoToolbox initialization/decoding cannot block the socket reader and its
control/input ACKs. The worker preserves dependent startup pictures, bounds its
steady-state queue and resets the reference chain on overflow. Ultra now keeps
an established peer alive through a short interruption (five-second idle
timeout), rather than destroying the window after a single second without an
authenticated packet. Startup keeps its existing 15-second budget. Reliable
keyboard/button delivery retains its separate fail-closed deadline.

The ordinary SNV2 host adapter now also forwards the existing per-peer bitrate
recommendation to the encoder. Previously it always returned the configured
target, ignoring sustained delivery deficits for a single viewer. Frame rate is
preserved; idle throughput and one transient feedback window do not lower the
budget. This is wiring the existing controller into the real encoder path, not
a new claim of a complete bandwidth estimator.

## Capture evidence when a session still fails

Both native endpoints emit bounded numeric transport counters: authenticated
traffic rejected, video datagrams, complete pictures, reference-wait drops,
NACKs, repairs, send-queue drops and stop reason. Automatic local connection
reports retain these and per-viewer sharing health, excluding viewer IDs,
endpoints, credentials and input content. The Mac viewer now also reports
decode/output progress, so a black window is distinguishable from a transport
that never received video.

Stop reasons: 1 = peer disconnect; 2 = peer timeout; 3 = input ACK timeout;
4 = priority queue overflow; 5 = transport exception. Decoder errors remain
available separately. A timeout is evidence of lost authenticated traffic,
not proof of a router/ISP fault.

Regression coverage includes a 256 KiB paced IDR followed by changing pictures
on one- and two-viewer UDP loopback, actual changing VideoToolbox pictures for
two surviving viewers, delayed NACK repair, bounded cache expiry and a brief
Ultra receive interruption. Existing slow-viewer isolation and codec tests stay
enabled. Real Mac/Windows capture, WAN latency and the reported ten-second
window exit still require testing on the user's two computers.

Multi-computer sharing remains **view-only and video-only**. The sound notice
describes that feature limit; audio is not added by this release. Ordinary
Mac → Windows Connect retains its legacy media pipeline. All 2.2.10 router
mapping, H.264 zero-reorder and earlier crash fixes remain included.

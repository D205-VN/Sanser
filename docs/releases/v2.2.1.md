# Sanser 2.2.1

This release includes view-only screen sharing for up to three computers in the same
account. A host captures/encodes once and delivers through independently
authenticated SNV2/H.264 peers. Mac and Windows keep their own native backends.

On the host: go online, select **Start sharing**, choose a computer and select
**Invite**. On each invited computer: select **Join**. **Remove** disconnects one
viewer; **Stop sharing** stops the group. The host's sharing indicator remains in
the application header across pages, with a floating native Stop indicator on
the shared host screen. Viewers cannot inject input at the host.

Update participating desktops and the server. This release carries forward the
2.1.22 Preview features and makes signed updates available through the latest
release channel. The updated server accepts supported 2.1.x and 2.2.x desktops
on protocol v2 during rollout; older desktops retain their existing feature
gates. View-only permission compatibility still starts at 2.1.22.
If the server explicitly sets `SANSER_VERSION`, update it to `2.2.1` or omit
the override so the compiled version is used.
The server advertises
`sharing-media` after applying migrations 0006–0007. Invitations do not grant
control. A viewer is shown as watching only after its native decoder reports a
first frame for the current session generation. A group from a previous app
lifecycle is paused until the user stops it and creates a new group.

P2P reservations, signaling receivers and relay bridges now support independent
viewer sessions. Pending relay connections are bounded, cancelled Direct ports
are released and a viewer can retry with a fresh readiness epoch. Logout cleanup
finishes before sharing is initialized again. Direct is preferred in Auto;
fallback uses the existing UDP relay where available, or encrypted WSS. Public UDP relay still requires actual
UDP ingress; a deployment cannot supply it on a platform that only accepts HTTPS.

The shared encoder adapts bitrate to authenticated delivery feedback from the
active viewers while preserving FPS. Sustained delivery deficits lower the
shared budget; healthy delivery recovers it gradually. Idle screens and transient
feedback do not immediately reduce quality.

Automated native/codec loopback, desktop and server
tests cover component behavior; real 2–3-computer Windows/Mac capture, GPU,
network and performance validation remains necessary. The previous ~200 ms route
latency is not claimed fixed. This release does not implement a privileged
Windows Secure Desktop service, audio sharing or mobile viewers.

# Sanser 2.3.6

This update focuses on Windows host input when opening an elevated game or
application. Install the Windows update and approve its administrator helper
installation before reconnecting.

- Resolve the protected Windows host once per launch. If enabled administrator
  support is broken or stale, report the failure rather than silently selecting
  the ordinary host that the broker cannot authorize.
- Verify the actual broker/worker input channel before starting an input-enabled
  session. The readiness probe sends no keys or clicks, runs off the GUI thread,
  and is also used by the Host readiness indicator.
- Report bounded numeric admission and worker-start errors instead of a closed
  pipe with no reason. Preserve executable-path, account, session, service
  identity and protected-file checks. Ambiguous timed-out input is not replayed.
- Prepare the official Windows installer toolchain through the public GitHub
  asset API, with bounded retries and pinned checksums, after browser download
  URLs repeatedly returned HTTP 504 on Windows runners.

The input patch passed 59 Windows native tests, including a real broker/worker
handshake and three privileged input events accepted by an elevated fixture.
The reported game on the user's Windows machine still needs retesting; this
release does not guarantee support for games that reject remote input.

The continuous Mac audio output and video scheduling from 2.3.5 are retained.
Android and iOS packages use version 2.3.6, build 20310. Android is signed locally
with the existing owner-held key. The iPhone IPA remains unsigned and requires
recipient signing before installation. Mac builds remain ad-hoc signed when no
Developer ID certificate is configured. Existing Voice Lab deployment and
physical-device validation limitations remain unchanged.

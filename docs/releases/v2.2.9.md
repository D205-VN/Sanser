# Sanser 2.2.9

Fixes the Mac native viewer crash reported with both computers on 2.2.7 when
joining a Windows multi-computer sharing session. The supplied crash report
identifies `NSEvent scrollingDeltaY` called from a mouse-move callback. AppKit
rejects that event/property combination and aborts the client.

The SNV2 viewer now reads wheel data only for scroll events and button data only
for matching button events. View-only windows reject mouse/keyboard input before
reading event-specific fields and cannot resume control by clicking the stream.
Control sessions preserve move/drag, left/right/middle clicks, scrolling,
keyboard, modifier and release/resume handling. Absolute pointer coordinates
respect the view's flipped coordinate system.

The session page no longer unconditionally says sound is unavailable for every
SNV2 session. Windows viewers of Mac hosts retain the implemented system-audio
path. Multi-computer sharing explicitly says it sends video only, and group
viewers do not request audio. This release does **not** add group audio or Mac
SNV2 audio playback. Ordinary Mac → Windows Connect retains legacy audio.

Regression tests run real AppKit move/drag/click/scroll/keyboard callbacks without
injecting OS input, including view-only and release/resume cases. An asymmetric
red-top/blue-bottom picture is encoded, transferred, decoded and rendered through
the production Metal renderer to check vertical orientation and letterboxing.
This synthetic test passes; the reported brief inversion on a Windows-generated
stream still needs physical retesting after the crash fix.

All 2.2.8 encoder-backlog, Windows presentation, crypto and measurement changes
remain included. Update both computers and test ordinary Connect and group
sharing separately.

The red overlay values in the supplied screenshot are latency budget overruns,
not additional crash messages. Same-socket UDP echo (~183 ms), Wire RTT (~182 ms)
and input ACK (~185 ms) agree while measured application queues are nearly zero.
Saved Oct 16 reports also show 2.2.1 Direct P50 at 184–186 ms and 2.2.7 at 185.6 ms;
their nomination probes were already 180–190 ms before media. These observations
do not identify the router, OS, ISP or VPN as the cause and do not demonstrate a
version-only regression. No 10–15 ms WAN latency fix is claimed here.

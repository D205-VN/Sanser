# Sanser 2.2.26

Update **both Windows and Mac**. This release targets Ultra latency on the
Mac viewer → Windows host path, retaining the UDP and audio recovery in 2.2.25.
App versions, native engines and signed updater artifacts are all 2.2.26.

## Ultra pacing and render scheduling

- Windows groups short Ultra pacing waits, allowing at most approximately
  500 microseconds of advance within a group of four datagram attempts.
  Absolute bandwidth deadlines, frame budgets and existing bounded idle credit
  remain in force. Auto retains its per-datagram pacing policy.
- Each datagram still uses its own authenticated packet and socket-lock scope.
  Timer grouping does not concatenate UDP payloads or remove input/audio priority.
- Mac Metal completion now wakes a pending newest-frame draw when the GPU was
  busy. Notifications coalesce into one main-thread draw and respect future
  presentation deadlines. Periodic fallback redraws remain available.
- Connection reports retain numeric pacing-wait/group and render-deferral/wakeup
  counters to help evaluate the change without recording screen or input content.

These changes target the legacy Mac → Windows Ultra pipeline. They do not
establish a measured latency reduction for Windows → Mac or Windows → Windows.

## Validation

The [source baseline passed all nine CI jobs](https://github.com/D205-VN/Sanser/actions/runs/40849291532),
including **40 Windows native tests** and **34 Mac native tests**. Regression
coverage includes GPU-busy completion wakeups, newest-frame preservation, idle
redraw suppression, bounded pacing groups and numeric report filtering.
Versioned source checks and installer builds run again for this release.

A virtual 256-datagram fixture used 50–75% fewer timer waits at 20/40/80 Mbps.
That is a count of waits, **not a measured percentage reduction in latency**.
Real two-machine comparisons of frame queue, pacing, dropped frames and P50/P95
remain necessary. Internet RTT and display scan-out are not eliminated.

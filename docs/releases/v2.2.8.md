# Sanser 2.2.8

This update targets the current Windows-client → Mac-host SNV2 pipeline. It does
not use 2.2.1 as a Windows → Mac performance baseline, and does not claim that the
reported three-second delay or the separate ~199 ms Direct RTT is proven fixed
on the affected physical computers.

Mac capture now hands off raw pictures to a worker with **one pending newest
capture**. One encoder submission is completed, including its output callback,
before the next picture is submitted. Slow encoding or packet preparation can
replace unencoded captures instead of accumulating an asynchronous VideoToolbox
backlog or blocking the capture callback. Encoded H.264 reference pictures are
not discarded this way. A cached idle picture is still available for a new
viewer, a keyframe request or recovery from a VideoToolbox frame drop.

Windows bounds each message-pump turn and paints a ready picture immediately.
Continuous queued messages therefore cannot keep the viewer draining messages
indefinitely while a new decoded picture waits to be drawn. Previous input,
display-aperture, decoder warmup and separate color-conversion fixes remain.

Windows native AES and HMAC processing reuse only their thread-local CNG algorithm
providers. They no longer reopen/configure a provider for every media packet.
Per-message hash state, symmetric-key handles and mutable IVs remain separate;
authentication, ciphertext format and session isolation are unchanged.

Automatic connection reports now retain SNV2 host encode-queue/encode-and-publish
timings, Windows decode/conversion/paint/decoded-to-paint timings, progress counts
and numeric input counts. The report also records the wire protocol and requested
codec/resolution. These are local processing measurements, not network RTT or
capture-to-display latency. Repainting an unchanged idle picture is excluded
from decoded-to-paint latency. Reports retain the existing bounded history and
numeric allowlist; they do not record keys, text, screen contents or credentials.

Regression tests block real VideoToolbox encoded delivery and verify that a
hundred superseded raw captures do not replay as a backlog: the original reference
and final newest picture still decode correctly. Windows tests exercise painting
with a provably nonempty message queue, and decode both the earlier Mac H.264
fixture and the new realtime fixture. Crypto stress tests interleave multiple
sessions across four threads and reject cross-session packets.

Update **both computers** to test this pipeline. Use ordinary Connect for
Windows → Mac control; group sharing remains view-only. Keep the same network,
resolution/FPS/bitrate and route during the comparison. Physical two-computer
screen/input latency must still be measured after installing the update.

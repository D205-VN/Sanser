# Sanser 2.2.17

Update **both Windows/macOS computers**. This release adds group microphone
conversation and packages the fixes developed after 2.2.16. Installers and native
engines carry the same version; signed updater artifacts use the latest channel.

## Group voice

In **Share with multiple computers**, the host and up to three viewers can talk.
Choose **Join voice** to listen, then **Unmute mic** to grant microphone access.
**Mute mic**, **Deafen voice** and **Leave voice** are independent of shared system
sound. Microphones default off and consent is not restored after an engine restart
or reconnect. Leaving the voice panel/page stops participation.

Voice uses mono Opus speech packets, per-speaker jitter/PLC, bounded queues and an
independent priority lane. The host forwards one encoded source to permitted
listeners without returning a speaker's voice to itself. Conversation remains
independent of a paused video path. Existing session authentication/encryption is
reused; there is no separate voice service, microphone recording or new port.

Mac excludes the host process's playback from shared system capture. Windows
uses actual process-loopback exclusion where available. If unavailable, shared
system sound pauses while the host listens to voice, then resumes after Leave or
Deafen, preventing a digital feedback loop. This is **not acoustic echo
cancellation**; use headphones. Noise suppression, AGC, per-person mute UI and
push-to-talk are not included.

## Fixes and optional Windows UAC support

- Restore audio opt-in on the ordinary Mac-controlling-Windows legacy path.
- Smooth PCM queue discontinuities and preserve video repair progress under
  continuous fresh traffic; audio/video recovery tests cover the regressions.
- Do not pause a sharing viewer merely because old keyframe backoff remains while
  fresh, clean feedback proves new completed frames. Handle Mac decoder output
  errors through the existing reset/keyframe recovery path.
- Preserve left/right Shift state on the Mac host for uppercase and combinations.
- Add **Host → Windows administrator prompts → Enable UAC support**. This optional
  local service supports capture/input during UAC and input to elevated installers,
  with protected per-account authorization and input cleanup. Enabling it requires
  local administrator approval; installing Sanser does not silently enable it.
  Lock/sign-in screens, other users and RDP remain excluded. After an app update,
  an already enabled helper may require **Update UAC support** before the next host
  session. See the setup/validation limits in [Windows UAC](../windows-uac.md).

## Validation and known limits

The preceding implementation CI passed all nine jobs, including 33 Windows native
and 27 Mac native tests, encrypted three-viewer synthetic voice, Opus loss/reorder,
consent/default-off/deafen, old-engine compatibility, process-activation lifetime,
scoped UI controls and actual UAC service setup/ACL/deny/uninstall checks. One
existing viewer-congestion timing test needed a rerun. These checks do not record
microphones, play hardware sound or establish physical-call quality.

Real microphone/USB/Bluetooth/permission testing, multi-person voice plus shared
music, UAC GPU/input on physical machines and long LAN/WAN/Relay sessions remain
necessary. Shared-screen freezes, crackling and roughly 200 ms paths/2 s observed
lag are not claimed universally resolved. Voice does not make a slow route faster.

Downloads: Windows x64 installer/portable, Apple Silicon Mac DMG/ZIP, signed updater
bundles, `updater-latest.json` and SHA-256 checksums. Without Apple Developer ID the
Mac bundle remains ad-hoc; macOS permissions may need to be regranted after updating.

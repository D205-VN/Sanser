# Sanser 2.3.12

The first Mac build signed with a stable identity, everyday Windows→Mac
shortcuts, a lighter Windows viewer and clearer group voice. 2.3.11 was tagged
but never published: its Mac signing step failed on a malformed secret.

- **Mac signing.** Releases are signed with the project's long-lived
  self-signed certificate instead of an ad-hoc signature, so Screen & System
  Audio Recording and Accessibility grants are meant to carry over between
  updates. **Grant once more after installing this version:** remove the old
  Sanser entries in System Settings → Privacy & Security, add
  `/Applications/Sanser.app` again and reopen Sanser. The build is still not
  notarized, so Gatekeeper warns on first open as before.
- **Windows controlling a Mac.** Ctrl+A, B, F, I, N, O, P, R, S, T, U, W, X, Z
  and Ctrl+Shift+Z are sent as Command by default, alongside Copy/Paste.
  Ctrl+Q is never mapped. Untick *Use Windows editing shortcuts on Mac* in the
  window menu to keep raw Control for Terminal or games.
- **Windows viewer.** The per-frame NV12-to-BGRA conversion is split across up
  to four row bands with byte-identical output: 1920×1200 measured 1.2 ms
  instead of 2.4 ms on a Mac. Decode and drawing remain software (Media
  Foundation, GDI); moving them to the GPU is the larger remaining fix.
- **Group voice.** Each speaker is encoded at 64 kbps fullband with Opus
  complexity 10, up from 32 kbps / 5. Noise suppression is unchanged.
- **Release workflow.** A malformed signing secret now produces an error that
  names the problem without printing either value.

The native suite passed 57 tests on macOS, including a new pixel-exact NV12
test and the extended shortcut test. The Windows viewer source was not compiled
locally; Windows CI is its first build. Neither the signed Mac update nor the
voice change has been checked on real devices yet.

Mobile version: 2.3.12, build 20320; the mobile app is otherwise unchanged.

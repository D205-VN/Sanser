# Sanser v2.1.7

- Fixed relay head-of-line blocking in the desktop bridge and server. Sending congested video no longer prevents the opposite direction from processing mouse/key traffic. Disconnect can cancel a blocked write.
- Disabled Nagle buffering on desktop relay connections and accepted server TCP sockets to reduce waiting for small control packets.
- Each native connection now automatically saves a local performance report: machine name, platform, app version, session ID, Direct/Relay route, requested FPS/bitrate, and the categorized result of the direct connection check.
- Mac-to-Windows sessions collect the native engine's input RTT, frame rate, capture/encode/decode processing times, render queue and dropped-frame measurements when emitted. Elevated RTT or processing/render delay is marked in the report. Missing measurements remain explicitly unmeasured; these reports do not claim a synchronized end-to-end screen latency.
- Reports retain the latest 120 samples plus maxima and delay counts for each of the latest 20 native engine launches. They are refreshed every five seconds and finalized at engine exit. Only fixed numeric metric fields are recorded: no session tokens, keystrokes, mouse coordinates or screen contents. Collection and disk writing are bounded and do not block the native stream.
- **Settings → Diagnostics → Export diagnostics** now includes the saved connection reports from previous sessions and app launches.

Update both computers. Connect normally, reproduce the delay for about 30 seconds, then export diagnostics on both devices. The matching session IDs let the reports be compared. A Relay route on the same LAN still needs investigation; this release records the direct-check failure category rather than assuming it is a firewall problem.

Validation includes a regression test that reproduces stalled input during a blocked video upload before the fix and passes afterward, report privacy/retention/persistence tests, and output-drain stress tests. Physical Mac-to-Windows latency remains to be measured on the affected computers.

The macOS app is ad-hoc signed, not Apple-notarized. Windows installers do not yet have an Authenticode publisher certificate.

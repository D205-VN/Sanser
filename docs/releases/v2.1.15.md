# Sanser 2.1.15

This release isolates Direct negotiation retries, separates Windows capture work
from DXGI waiting, and makes Windows stream adaptation preserve FPS under network
pressure. Update **both computers** before testing Direct: candidate generations
now use the server-issued connection epoch, including its normalized ISO form in
the desktop app. Older desktop builds use generation 1 and cannot negotiate a
Direct route with this generation scheme. Auto retains relay fallback.

- Candidates and acknowledgements from earlier retries are ignored. A new retry
  also gets a fresh server candidate budget. This fixes stale negotiation state;
  it does not guarantee UDP traversal through every NAT/firewall.
- When all three GPU capture textures are busy, Windows skips that capture and
  lets the encoder drain instead of silently copying the desktop back to RAM.
  Existing rotated-display and encoder-error CPU fallbacks remain supported.
- The Mac overlay and connection reports distinguish **Capture work** from
  **Capture wait**. Work excludes `AcquireNextFrame` waiting; its average counts
  successful fresh captures rather than encoded/drain iterations. GPU copy work
  is enqueued asynchronously, so this is CPU-side capture timing, not a GPU
  completion measurement. Host workload now includes capture and preparation,
  while excluding acquisition wait.
- Sustained loss, failed repair, or sustained send overload reduces bitrate by
  12% per statistics window (16% for loss of at least 4%), at most once per window
  across feedback sources. Jitter/absolute RTT alone does not cut bitrate. These
  network reductions keep FPS unchanged. Existing cautious recovery gates and
  bitrate warmup remain; this is not yet a bandwidth-estimating congestion controller.
- Processing overload can reduce FPS without also cutting bitrate. Reductions
  cannot compound across host/client processing reports in the same window.
  Normal newest-frame coalescing alone no longer triggers an FPS reduction.
  Startup bandwidth warmup no longer halves requested FPS.

Regression coverage includes stale candidates/receipts, Unix/ISO epoch handling,
host/viewer propagation, duplicate congestion reports, interrupted loss streaks,
bitrate-first trajectories and capture-wait reporting. Physical Windows GPU,
LAN/WAN Direct traversal, image quality and end-to-end latency still need measurement.
No claim of 5–15 ms latency is made.

This release does **not** replace WSS media relay or migrate the server to a Mac.
A public UDP endpoint is still required before deploying a UDP/QUIC relay.

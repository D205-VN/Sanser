# Sanser 2.1.16

This release improves Direct discovery, adds an optional authenticated UDP media
relay, and updates Mac input retries and Windows bitrate adaptation. Install it
on **both computers**.

- Direct STUN requests retry within the existing gathering deadline. Candidate
  selection preserves distinct LAN/STUN/mapped routes when many interfaces are
  present; responses from the wrong server port or old transactions are ignored.
- Updated clients try UDP relay when Direct is unavailable. Both peers must prove
  UDP reachability before it is selected. Media/input remain end-to-end encrypted;
  WSS handles authentication and allocation lifecycle. Lost video datagrams do not
  hold later input behind TCP retransmission. Legacy or unreachable UDP servers
  retain the encrypted WSS fallback.
- Diagnostics identify UDP versus WSS relay and save the actual transport in
  connection reports. The relay does not assume it is using UDP merely because
  the native sidecar communicates over local UDP.
- Gamepad snapshots use latest-state delivery in Auto as well as Ultra. Reliable
  input retries follow fresh network RTT; exhausted UDP retries send an
  acknowledged reset to avoid held keys.
- Mac feedback reports accepted unique video bytes before decode. Windows uses
  measured delivery, offered rate, RTT trend and socket work when reducing
  bitrate under sustained pressure. Idle traffic does not cap bandwidth and
  network pressure keeps FPS stable. Existing recovery gates remain.

**Deployment requirement:** UDP relay must be explicitly configured with
`RELAY_UDP_BIND` and `RELAY_UDP_PUBLIC` on a server with reachable UDP ingress.
Updating the apps alone does not replace Render, expose a Mac behind NAT, or
remove WSS fallback. See [UDP relay setup](https://github.com/D205-VN/Sanser/blob/Version-2.0.0/docs/udp-relay.md).

Automated coverage includes real local UDP forwarding with packet loss/reordering,
allocation authentication/expiry, lost registration retry, legacy server fallback,
input retry timing and bandwidth adaptation traces. These are not real-device
LAN/WAN benchmarks. Windows GPU behavior, image quality and end-to-end latency
still need physical testing; 5–15 ms is not guaranteed. UDP is implemented here,
not QUIC, and a dedicated priority-lane scheduler remains future work.
